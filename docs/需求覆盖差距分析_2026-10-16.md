## 〇、总体格局

**扎实（可直接依赖的底座）**
- 租户隔离：Prisma 扩展层全局强制注入 tenantId（`prisma.service.ts:33-51`，忘写 where 不泄漏）+ DB REVOKE 双保险
- 审计：AuditLog 哈希链、28 个红线动作、三层防篡改（`audit.service.ts`）
- 资金账本：应收/库存全 append-only 流水投影，FIFO 核销 FOR UPDATE 串行化，红字冲正，幂等键
- 价格主链路：五级价版本化 + 一客一价最高优先 + 订单行价格快照 + 调价审批
- 信用控制：下单/审单双卡点，占用口径=已欠+在途未签收，超额特批走 CREDIT_RELEASE
- 审单四要素、拒收双回滚、盘点双签审批、押金台账、工资表一键生成均有真实闭环

**系统性缺口（五条线）**
1. **费用域整体空白**：无 Expense 模型——办公费用(M4-3)、开瓶费(M3-4)、陈列费/进店费(M3-5)、油费路桥等台账(M10-3)全无；EXPENSE 审批线是死字符串
2. **主动触达几乎为零**：定时任务仅库存日切一处；到期提醒是拉取式接口、无催款分级、对账单不自动生成、归档无任务触发；无微信订阅消息
3. **毛利/成本分析空白**：销售报表不 join 成本，无客户/品类/单品毛利，无促销侵蚀还原
4. **促销规则引擎缺失**：买N送M靠手工标 isGift、返利无坎级阶梯、开瓶费/瓶盖兑付零代码
5. **配置化承诺未兑现**：品类死枚举、账龄档位硬编码、返利费率区间硬编码、审批线归属硬编码、ABC 无规则

**⚠️ 实现与已确认需求冲突（优先修正）**
| 冲突点 | 代码现状 | 需求（已确认） |
|---|---|---|
| 账龄档位 | 硬编码 1-30/31-60/61-90/>90（`receivables.service.ts:33-38`，前端同步硬编码） | **30/50/90**（Q1 已于 2026-09-19 确认），且须租户级可配 |
| 返利费率区间 | `rate >= 0.05 && <= 0.5`（5%-50%，`rebates.service.ts:23`） | **1%-50%**（客户 v1.1 明确修订） |
| 返利形式 | 仅 GOODS/INVOICE 两态 | 需求含**现金**形式 |
