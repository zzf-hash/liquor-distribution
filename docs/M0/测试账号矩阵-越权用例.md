## 1. 五角色测试账号矩阵

来源: `apps/api/prisma/seed.ts`(演示 seed, `pnpm seed` 落库)。演示密码统一 `demo1234`(bcrypt 存储)。

| 用户名 | 姓名 | 角色(Role) | 数据范围(dataScope) | 信道(aud) | 备注 |
|---|---|---|---|---|---|
| `owner` | 朱总(老板) | OWNER | ALL | staff | 全数据可见, 审批/抹零/坏账核销权限 |
| `clerk` | 小王(内勤) | CLERK | ALL | staff | 订单池/应收/主数据 CRUD |
| `rep1` | 李业务员 | REP | OWN_CUSTOMERS | staff | 只见自己名下客户, 代下单/收款上报 |
| `warehouse` | 老张(仓管) | WAREHOUSE | SELF | staff | 拣货/发运/签收, 库存可见但不可改单 |
| `cust-c0001` | 张三(客户登录) | CUSTOMER | SELF_ORDER | customer | 绑客户档案 C0001, 走客户信道, 仅商城接口 |

- **role = 能力面(接口守卫)**: 决定「能不能调这个接口」(RBAC, `RolesGuard`)。
- **dataScope = 行范围面(行过滤)**: 决定「能看/改哪些行」(service 层按 dataScope 过滤, `PrismaService $extends` 强制注入 tenantId)。
- 两面正交(安全评审 2.1 两张正交表): 角色对 ≠ 行范围对。客户信道(aud=customer)与内勤信道(aud=staff)物理隔离, 客户令牌调内勤接口一律 403。

## 2. 越权 / 禁用 用例清单(逐条 → 单测断言)

「正常」= 应放行(200/进入业务)；「异常」= 应拒(401/403/拒绝)。满足验收「≥3 正常 + 2 异常」(实际 4 正常 + 11 异常)。

### 2.1 AuthGuard(令牌 / 禁用 / 吊销 / 租户) — 每请求回库, ≤1 请求周期生效

| # | 类型 | 用例 | 预期 | 单测 |
|---|---|---|---|---|
| A1 | 正常 | `GET /api/health` | 200 免鉴权 | `正常①` |
| A2 | 正常 | `POST /api/auth/login` | 200 免鉴权 | `正常②` |
| A3 | 正常 | 有效令牌 + ACTIVE + tv 一致(OWNER) | 200, 建租户上下文 | `正常③` |
| A4 | 正常 | 有效令牌 + CUSTOMER(aud=customer) | 200, 客户信道 | `正常④` |
| A5 | 异常 | 缺 Authorization 头 | 401 未登录 | `异常①` |
| A6 | 异常 | 无效 / 过期 JWT | 401 令牌无效或已过期 | `异常②` |
| A7 | 异常 | 令牌指向已删除账号 | 401 账号不存在 | `异常③` |
| A8 | 异常 | **账号被禁用**(status=DISABLED) | 401 账号已禁用(B1 即时生效) | `异常④` |
| A9 | 异常 | **令牌被吊销**(JWT.tv 落后于库 tokenVersion) | 401 令牌已失效(B1 即时吊销) | `异常⑤` |

### 2.2 RolesGuard(RBAC 角色面 + 信道分离)

| # | 类型 | 用例 | 预期 | 单测 |
|---|---|---|---|---|
| R1 | 正常 | 接口未声明角色约束(已登录) | 200 放行 | `正常①` |
| R2 | 正常 | OWNER 调 @Roles(OWNER) | 200 放行 | `正常②` |
| R3 | 正常 | CUSTOMER 调 @Roles(CUSTOMER) 客户接口 | 200 放行 | `正常③` |
| R4 | 异常 | **REP 越权调 @Roles(OWNER)**(业务员调老板接口) | 403 当前角色无权限 | `异常①` |
| R5 | 异常 | **客户令牌调内勤接口 @Roles(CLERK)**(信道分离) | 403 客户身份不可调用内勤接口 | `异常②` |
| R6 | 异常 | 有约束但 req.user 缺失(未过 AuthGuard) | 拒绝(false) | `异常③` |

## 3. 跨租户不可见(B5) — 服务端统一实施

不在守卫层, 而在 `PrismaService.$extends`(安全评审 B5): 所有 `TENANT_MODELS` 的查询自动补 `where.tenantId`、写入自动补 `data.tenantId`; 即使业务代码忘写 where 也不会跨租户读/写。第二层防线为 PostgreSQL RLS。本单(越权/禁用)的 401/403 面由上面两表覆盖; 跨租户「读不到」面由 B5 注入保证(见 `docs/M0/安全评审-01.md`)。

## 4. 小程序登录通道

`apps/miniapp/src/services/api.ts`: 员工账密登录 `POST /api/auth/login`(按 role 跳首页 `staff/login`), 客户走微信登录。401 文案区分: 登录 401=账号/密码错; 受保护接口 401=令牌过期/被吊销(由 AuthGuard A6/A8/A9 抛出的 `UnauthorizedException` 统一经 `HttpExceptionFilter` 转 `{code:401}` 外壳)。

## 5. 如何复跑

```bash
cd apps/api && pnpm exec tsc --noEmit   # 类型绿
pnpm --filter @liquor/api test          # jest: shared.spec.ts + auth-guards.spec.ts 全绿
```

线上验证(liquor-sg, 经 nginx `/api` 前缀, 不剥前缀):
- 禁用某 demo 账号后, 其未过期 JWT 下一次请求即 401「账号已禁用」(A8)。
- 吊销: 登录拿 JWT → 改库 `tokenVersion+1` → 同一 JWT 再请求 → 401「令牌已失效」(A9)。
- 客户令牌打内勤接口 → 403「客户身份不可调用内勤接口」(R5)。
