## 1. 任务点名六项规则冻结

### D1 特单审批（Q1，审批线②）—— 保留（简化为单一状态机+金额路由）
- 矛盾点：角色清单「企业主特批」vs F8 流程「内勤审批定价」。
- 冻结：特单命中任一即标——①成交价低于该客户当期可用价；②非默认收货地址；③指定配送时段；④宴席/活动用酒；⑤约定回款日超账期。审批按金额分级：单笔 ≤ 阈值 T（**默认 2000 元，可配置**）内勤定价审批；> T 或成交价<成本价 → 老板审批；审批人唯一，系统按金额自动路由，不允许自选审批人；超时 24h 订单退回待处理，不自动通过。
- P0/P1 分层：P0-09 只做「信用/价格超限拦截+老板单级特批+全链路留痕」；特单完整字段流 P1-02 交付；多签/品类路由 → P1-01 统一审批中心。
- 联动：改价审批线（①）同走本路由。红线：未经定价审批不可出货（P1-02 验收）。

### D2 返利口径（Q2，R3 优惠三式）—— 保留（简化：一期不做预提负债与跨期摊销）
- 冻结：b（除瓶箱后 5%–50%，月末核算，货补/票折二选一）与 c（定扣货款）**互斥使用**，同一客户同期只允许一种返利方案生效；c 记账 = **直接冲应收**（不做预提负债，与「ERP 总账不纳入」边界一致）。
- 新增约束（采 v1.0-NAS）：b、c 之外的随单促销让利，单笔合计默认 ≤ 该单毛利 50%（防价格倒挂），老板可配放开。
- P0 边界：价格引擎 P0 只做五级价+一客一价+订单快照（P0-05），任何返利/促销计算不进 P0；P0-13 应收模型预留 `rebate_scheme` 字段。
- 赠品账务口径（采 v1.0-ext，关键）：赠品行 0 单价参与库存扣减，但**不参与账龄、不占信用额度、不计提成基数、不计促销让利上限**；赠品退货须同单退。货补兑付以「收款-返利兑付」类型入账，不反改原单金额（保订单快照不可变）。
- 延期边界：预提负债/跨期摊销若财务要求 → 变更评估，最早 P2；厂家返利自动结算维持计划书 §1.2 排除。

### D3 网签占比与纸单双轨（Q3，R8）—— 保留 + 简化 + 新增
- 定义冻结：网签 = 小程序/移动端完成电子签收（点选+签名/拍照）；非网签 = 打印送货单纸质签字 + 内勤回录。**占比按订单来源单数计量**（采 v1.0-ext；系统单=客户自主+业务员代下；非网签=电话/微信录入+纸单回录），试点期实测回填基线，运营指标走计划书 §8「系统订单覆盖率」。
- 双轨为 P0 硬功能（红线 4：纸质客户不得被流程阻断，必须进待回录工作池；回录必须关联原订单号，补录时限默认 D+1）。
- 打印裁定：一期基线 = **Web 端浏览器打印 A4/B5 通用套打模板**（不绑定针式型号，消除 v1.0-NAS「针式三联」与 v1.0-PC「浏览器打印」冲突）；针式三联（241 宽）/热敏小票作为 M0-04 兼容性验证候选项，选型只影响驱动适配层不影响单据模型；专用驱动适配 → P2 单独立项。
- 电子签效力：签名照片+拍照+时间戳 = 商业对账依据，不做司法存证；若老板要司法效力 → 第三方电子签单独立项（成本/周期另评）。

### D4 账龄口径（Q5，R2/D7）—— 简化后冻结（原「超 3/5/910 天」表述收敛为标准分档）
- 状态口径：**未到期 / 逾期 1–30 / 31–60 / 61–90 / >90 天**（四档逾期，可配置）。
- 起算：应收单生成日 = **出库签收完成时刻**；到期日 = 生成日 + 客户账期天数（现结账期 0，生成即到期）。月结基准日默认每月 25 日结单、次月 10 日到期，配置项落库（改配置只影响新单，不回算历史）。
- 核销顺序：**最早到期优先**（到期日同按生成先后），禁止比例分摊；部分收款允许、逐单冲抵。P0 不做挑单核销（→ P1-08 差异工作池，必须留痕）。
- 升级链：客户端提醒→业务员提醒→上门→**>90 天自动打「建议停货」标签（停货动作须老板审批）**→法律（线下）。
- 唯一算法约束：FIFO 冲抵为账龄唯一算法（P0-13），禁止多算法并存；分档天数=老板端配置项。
- 争议/死账标记（采 v1.0-ext）：不参与账龄分档与自动提醒，只进看板欠款总额单列。

### D5 绩效归属（Q8，R10）—— 保留 + 新增
- 冻结：三项绩效（月开发新客/月拜访/月销售产品数）**全部以回款计**；回款业绩归属 = **下单时点客户 owner 快照**（固化进订单，客户后续转归属不回算历史单，与价格快照同原则）；跨月回款计回款发生月、追溯原单归属。
- 催收/协助：催收人、代下单人记「协助」明细项，**记录不分成**（防重复计薪；一张单只允许一个归属人）。v1.0-NAS 提出的「超 1 个月未回款由他人催收完成归催收人」列为老板可选变体 B，**默认关闭**，开启需签字。
- 团队单：一期不存在，每单唯一 owner；多业务员比例分成 → P2 单独立项。
- P0 强制字段：订单表「责任业务员」P0-08 起强制（归属锚点），绩效计算与工资表 P1-09 交付、工资表可复算。
- 退货/拒收冲减：冲减当期业绩，不回算历史工资（保 P1-09「可复算」验收成立）。赠品/返利抵扣/争议款/协助单不计基数。
- 新增留痕：客户业务员变更须审批留痕，变更不回溯已生成订单。

### D6 部署形态（Q12）—— 保留（消除「私有 vs SaaS」二选一悬置）
- 冻结：**首日即多租户架构（全部业务主表带 tenant_id、权限服务端统一实施），首期只开 1 个生产租户（本商户）——按 SaaS 建、按私有交付**。后续加商户零重构；SaaS 运营功能（注册/计费/多租户运维）本期不投入。
- 部署 = 单机 Docker Compose + Nginx，测试/预生产/生产三级环境可复现；对象存储用云厂商（OSS/COS 与小程序同生态二选一）；私有化单机分叉路线删除。
- 备份恢复：每日全量 + WAL 归档保留 30 天，数据变更必须迁移脚本，**恢复演练一次为 M0-04 出口条件**；生产发布可回滚。
- 与 b7df51db 安全评审联动：B5「tenant_id 第一天进表」即本决策的执行层保证；架构师在 P0-02 评审 Guard/租户中间件时引用本文为基线。

## 3. 数据迁移口径冻结（M0-03 联动，P0）

| 项 | 冻结结论 |
|---|---|
| 基准日 B/T | 上线切换前最后一个工作日 24:00 闭账；B 前**已结清单据不迁明细**，仅按客户汇总期初余额；B 时点**未结单据必须逐单迁移**（无逐单记录的老账按「最后收款日」重算到期锚并进差异报告签字）——保证账龄可算是 D4 成立的前提 |
| 期初应收 | 粒度 = 客户×原始单据，**不接受只导汇总数**；未结=应收−已收 逐行 0 容差硬校验；全批合计=商户签字台账合计，不符整批拒；争议/死账单独标记（只进看板总额，不进账龄与提醒） |
| 期初库存 | 按「商品×批次」导实盘+批次进价；批次管理商品（酒类默认是）批次号必填，非批次商品批次号=**「期初」**（模板口径）；啤酒/效期品生产日期+到期日必填、已过期批次拒入；数量与金额内勤+老板双签；库位必填高值品锁定区 |
| 商品编码 | 商户现用 Excel 编码沿用，整表唯一强校验；无编码商品系统按「品类拼音+5 位流水」生成后回填台账；同名称+规格+单位不同编码 = 疑似重复进差异报告人工合并，禁止系统静默去重 |
| 客户主数据 | 「客户编码」为唯一键；同手机号多店需备注、首店自动绑定其余人工确认（疑似重名/同电话进差异报告人工裁决，禁止系统静默去重）；存量迁移客户「状态=有效」直接导入（视同已终审，字段规范口径），新增客户一律走系统开户流程（不可被导入绕过） |
| 价格 | 同（客户,商品,单位,价型,生效日）完全重复 = 拒后条并进差异报告（字段规范 R-拒行）；区间重叠但生效日不同 = 警告，商户裁决（取价引擎按最新生效日兜底）；失效日<生效日拒；专属价必须带审批单号（缺=差异提示） |
| 回滚 | 每批生成 `import_batch` 批次号，五类可按依赖序（商品→客户→价格→库存→应收）分单提交、同批次号整批回滚；失败批次零写入（P0-07 验收）；已提交批次作废走**冲正流水不改库**（对齐 §4.2 不可变流水与安全评审 B4） |
| 签字控制点 | 商品编码、客户名称、应收余额三项商户签字后方可切账（计划书 §6.3）；每表负责人签字（商品/客户/价格=内勤、库存=仓管、应收=财务/老板）拍照随文件交回（字段规范§6 作业清单）；应收批次无签字=不生效 |

## 2. P1 决策项（4 项，未确认项均有默认方案 + 延期边界）

### D13 退货与宴席余货退回 —— **简化**
- 保留口径：退货数量「只能改多不能少」（P1-03 验收），退货入库后应收自动重算。
- 宴席余货退回 **默认方案**：签收后 48h 内、须关联原单 + 老板审批；退回商品按原批次回冲库存，应收按实退回重算。
- 争议点已裁定（关键）：退回 **不** 回算历史工资，按当期冲减（与 D05 同一口径）。
- 延期边界：M2 前只走「出库修正单 + 人工调账」，不自动重算；自动重算随 P1-03 上线。
- 拍板人：老板 / 落地方：backend。

### D14 回包装与押金 —— **简化**
- P0：仅「回填登记 + 台账」（有单回填、无单回收），不参与账务。
- P1-04：周转箱押金台账落地；押金单价、按客户/品类对账规则由冻结会确定。
- 删除：押金自动收付、押金抵扣货款（P2 再评估）。
- 拍板人：财务 / 落地方：backend。

### D15 促销费用（随单赠 / 定扣 / 开瓶费 / 库存增贬值） —— **简化**
- P1-05 只做：随单赠、满赠门槛、调价审批 + 价格版本（与 D08 对齐）。
- 定扣、开瓶费 **默认方案**：只登记不建账务，表结构预留财务凭据字段。
- 库存增贬值：P0/P1 不做自动估值，盘点差异走 P1-07 报损审批。
- 延期边界：促销规则引擎（多规则叠加/互斥）→ 冻结后单独立项，M2 内不做叠加促销。
- 拍板人：老板 + 财务 / 落地方：backend。

### D16 AI 语音 / 照片转单 —— **保留（强约束）**
- 硬约束：结果永远是「可编辑草稿」，**不得**直接生成出库指令（体验红线 2）；低置信度必须强提示。
- 上线门槛：样本草稿字段准确率 ≥90%（P1-10 验收）；按品类/客户别名积累词典。
- 延期边界：M2 末未达 90% → 顺延至 M3，且 M3 须按计划书 §1.3 做 ROI 复盘后单独立项，不默认排期。
- 拍板人：老板 / 落地方：backend + frontend。

## 3. 体验红线（不可谈判项，作为全部 P0 任务的验收附加条件）

计划书 §2.3 五条全部作为**验收硬门槛**纳入 P0 各单，不降级、不后移：

1. 客户侧不出现内部术语（库存批次、信用额度、欠款），拦单只展示「请联系业务员/内勤处理」。
2. 语音/照片识别结果永远是可编辑草稿。
3. 对客户可见的价格必须来自订单价格快照；历史单据不得因后续调价改变。
4. 网签与纸质单并行时，纸质客户不被流程阻断，必须进待回录区。
5. 任何影响库存/应收/价格的动作必须显示结果摘要 + 二次确认 + 审计记录。

易用性量化指标（§2.1 表）作为 P0-08/P0-10/P0-15 的界面验收项：首页仅语音/拍照/文字三入口、首次下单 ≤3 分钟、代下单 ≤60 秒、电话单转草稿 ≤30 秒、关键按钮 ≥44px、审批 ≤3 次点击、日报打开 30 秒见重点。
