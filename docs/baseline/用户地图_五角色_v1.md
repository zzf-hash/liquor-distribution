# 订货商城 · 用户地图（五角色用户视角）v1.0

> 2026-09-21 · 依据《订货商城_业务需求梳理_v1.md》
> 视角约定：不写"系统有什么功能"，只写"用户在什么场景下、想干什么、现在怎么受苦、用系统后长什么样"。
> 用法：① 指导各端首页与信息架构；② UI 设计的场景清单；③ 验收时按旅程走查。

## 1. 一页总览

| 角色 | 一句话目标 | 主用端 | 使用频率 | 典型场景数 | 首页应该是什么 |
|---|---|---|---|---|---|
| 客户（终端店老板） | 下单别让我打字，欠多少钱一目了然 | 小程序 | 缺货时/每天 1-2 次 | 6 | 大按钮三式下单 + 今日应到货 + 欠款金额 |
| 业务员 | 少填表多卖货，绩效自己看得见 | 移动端 | 全天在外 | 9 | 今日拜访计划 + 待办（确认单/催收/审批结果） |
| 出纳/内勤 | 录单快、账对得上 | Web 端 | 全天（系统最重度用户） | 10 | 订单池（待确认/待打单/待回录） + 今日收款 |
| 仓管/配送 | 送对货、签收留证、空瓶对得上 | 移动端 | 全天（库+在路上） | 8 | 今日拣货单 + 配送路线 + 待入库 |
| 企业主 | 四问有答案，审批不超过三击 | 手机（小程序/H5） | 每天 3-5 次碎片 + 月度 | 7 | 四问看板 + 审批待办红点 |

## 2. 协作全景：一张订单穿过五双手

```
 客户        业务员         内勤/出纳       仓管/配送        企业主
  │            │               │               │              │
  │ 缺货:语音/  │               │               │              │
  │ 拍照/文字   │               │               │              │
  ├──────────►│  确认审单      │               │              │
  │            │ (信用/价格/    │               │              │
  │            │  库存预检)     │               │              │
  │            ├──────────────►│ 开单/打印      │              │
  │            │               ├──────────────►│ 拣货(FIFO)    │
  │            │               │               │ 复核装车      │
  │  收货点数   │               │               │              │
  │◄───────────────────────────────────────────┤ 送货卸货      │
  │  网签+回包装 │               │               │              │
  ├──────────►│  (代收现结)     ├──────────────►│              │
  │            ├──────────────►│ 回录/销账 ─────┼─────────────►│ 看板实时+
  │            │               │ 清账通知       │              │ 日报推送
  │◄────────── ┴────────────── ┴───────────────┴───────────── ┤
  │  月底: 账期提醒 → 对账确认 → 付款 → 清账通知                │
```

关键交接点（最容易掉链子的三处）：
1. **业务员→内勤**：口头单/微信单转系统单（用语音草稿消灭手抄）
2. **配送→内勤**：纸质单回录（非网签客户，双轨并存期最重的人工活）
3. **内勤→客户**：月度对账（无系统时 1-3 天，扯皮重灾区）

## 3. 客户（终端店老板）

### 3.1 画像
- 微信重度、打字慢、语音习惯；手机字体偏大；信任"看得见的价格"
- 关心三件事：**价格别乱、货别送错、账别算错**

### 3.2 旅程

**场景 A：缺货下单（核心场景，一天 1-2 次）**

| 步骤 | 用户做什么 | 系统长什么样 | 今天（无系统） | 痛点 |
|---|---|---|---|---|
| 1 | 打开小程序 | 大按钮：「按住说话」「拍照下单」「打字」 | 打电话，占线就等 | 电话高峰打不进 |
| 2 | 按住说："明天送 10 箱雪花 8 度、2 瓶汾酒，老价格" | 实时转写 → AI 解析成商品+数量草稿 | 口头说，靠内勤笔记 | 说错/记错 |
| 3 | 瞄一眼草稿，改个数量，点确认 | 草稿可编辑；**每行直接显示我的专属价** | 价格靠记，月底扯皮 | 价格不透明 |
| 4 | 提交，显示"周三东线送达" | 按排线自动给预计送达日 | 不知道哪天到 | 等货焦虑 |

**场景 B：收货**
- 卸货 → 点数 → 手机网签（或纸质签字留客户联）→ **顺手填回包装**：纸箱几个、周转箱几个 → 现结客户当场付款
- 痛点今天：签完的单丢了说不清；周转箱数量月底对不上

**场景 C：月底结账**
| 步骤 | 系统长什么样 | 今天 |
|---|---|---|
| 账期前 3 天 | 小程序自动提醒："您有 12,800 元 9/28 到期" | 业务员想起来才催 |
| 查账 | 未结款电子单据一览，一笔一笔可点开 | 翻纸质单/微信记录 |
| 对账 | 收到对账单 → 逐笔确认/标异议 → 双方确认 | 对一次账 1-3 天，扯皮 |
| 付款后 | 收到清账通知；已结单据可查 6 个月 | 无凭据 |

**场景 D：退货**：找业务员 → 业务员现场清点填报 → 我签字确认 → 后面不用管
**场景 E：查历史**：上个月那 2 箱啤酒多少钱拿的？→ 单据列表搜一下
**场景 F：改主意**：下单后 10 分钟发现多订了 → 单据详情改/取消（配送前可拦）

### 3.3 客户端设计红线
- 首页 ≤ 3 个主按钮；字号大；**专属价必须直接可见**（不进详情页）
- 永远给"人工兜底"入口（一键拨内勤）
- 不让客户理解"批次/信用额度"这些内部概念

## 4. 业务员

### 4.1 画像
- 全天在外、单手操作手机、路上时间多；既要卖货又要当"人形催收机"
- 关心三件事：**客户信息随身带、录单别重复劳动、绩效透明别被算错**

### 4.2 一天的旅程

| 时段 | 场景 | 用户动作 | 系统长什么样 | 今天 |
|---|---|---|---|---|
| 8:00 | 出发前 | 看今天跑哪些店 | 今日拜访计划（A 类每周 2 次/B 类 1 次/C 类半月），按路线排好 | 靠脑子/本子 |
| 9:00 | 到店打卡 | 拍门头照 | 水印相机：时间+定位+工号，不可改 | 老板不信我去过 |
| 9:10 | 拜访八步 | 查库存→理货陈列→贴宣传 | 终端库存录入/拍照、陈列照片上传 | 本子记，回不去就忘 |
| 9:30 | 接单 | 对老板说："要啥直接讲" → 语音代录 | 按住说话→草稿→现场让客户看一眼→确认 | 手抄单，回公司再录一遍 |
| 10:00 | 收欠款 | 收现金/微信 | 收款登记（金额+方式+凭证照） | 私聊转账老板，说不清 |
| 11:00 | 新店开拓 | 谈价：谈优惠三式（搭赠/返利/定扣） | 开户表单：店名/位置/证照拍照/电话/账期/额度/**价格方案**→提交 | 回去口头转述内勤录 |
| 14:00 | 特单 | 饭店要宴席用酒，要特价 | 特单申请：品名/数量/价格/配送时间/**地址定位**/联系人/收款人 | 打电话一层层传 |
| 15:00 | 催收 | 收到系统推送"XX 店超期 5 天 3,200" | 超期列表按金额排序，顺路先去大户 | 老板催才动 |
| 17:00 | 收工 | — | 今日小结：拜访 8 家/接单 5 张/收款 4,300 | — |
| 月底 | 绩效 | 看三指标 | 月新客户数/月拜访数/月销售（**以回款计**）进度条 | 拍脑袋，被质疑 |

### 4.3 高频痛点 → 解法

| 痛点（今天） | 系统解法 |
|---|---|
| 一个单录两遍（手抄+回公司录） | 语音代录草稿，现场确认即入池 |
| 客户专属价记不住，报价心虚 | 客户详情直接带出专属价+历史成交价 |
| 打卡没证据、竞品信息带不回来 | 水印打卡+拜访产出结构化（陈列照/竞品/终端库存） |
| 催收凭感觉 | 超期自动推送+按金额排序 |
| 绩效算不清 | 三指标实时进度，每笔可追溯到源单据 |

## 5. 出纳/内勤

### 5.1 画像
- Web 端重度用户，键盘流；电话、微信、司机、老板四线作战
- 关心三件事：**录单快、单不丢、账能对上**

### 5.2 一天的旅程

| 时段 | 场景 | 用户动作 | 系统长什么样 | 今天 |
|---|---|---|---|---|
| 8:30 | 过夜单 | 过商城自助单 | 订单池：待确认区，预检结果标红（超额/缺货） | 无此概念 |
| 9:00-11:00 | 电话高峰 | 接单：**按住说话复述客户原话** → 实时转写 → 草稿 → 确认 | 复述式录入：转写可编辑，AI 已带出客户（来电反查）和专属价（"老价格"） | 手记便签，挂电话再录，高峰必漏 |
| 11:00 | 打单 | 非网签客户打送货单 | 勾选→云打印，留客户联 | 手写四联单 |
| 12:00 | 到货 | 核对仓管入库单，确认采购 | 采购单确认（先付：此时催老板审批→付款） | 微信问老板 |
| 15:00 | 司机回库 | 收纸质单，回录签收+回包装 | 待回录区：对着纸质单补录，异常（拒收/破损）一并处理 | 再录一遍 |
| 16:00 | 收款 | 录业务员上报的收款 → 销账 | 一键销账→自动发清账通知 | 手工记账+微信通知 |
| 16:30 | 开户确认 | 审业务员提交的新客户 | 开户待办：核对档案→确认→流转老板终审 | 口头/微信 |
| 月初 | 发工资 | 工资表一键生成（底薪+绩效） | 一键，可钻取每人绩效明细 | 做 3 天，全员来对质 |
| 月初 | 报表 | 月报表/库存表一键 | 一键 | Excel 手搓 |
| 对账期 | 月结 | 生成对账单→推送客户→差异标记（漏单/价格/赠品/退货）→核销 | 差异智能匹配，当日闭环 | 1-3 天，扯皮 |

### 5.3 痛点 → 解法

| 痛点 | 解法 |
|---|---|
| 高峰期接单漏单 | 语音复述录入 30 秒/单；未确认单在池里不会丢 |
| 录两遍（回录纸质单） | 推动网签；非网签期保留待回录区 |
| 老板审批找不到人 | 审批推送+超时提醒 |
| 工资/报表手搓 | 一键生成，明细可追溯 |
| 历史应收一团糟 | 期初导入+账龄列表 |

## 6. 仓管/配送

### 6.1 画像
- 移动端、仓库光线差/户外阳光强、手常有油污；装卸搬运一身兼
- 关心三件事：**拣不错、送得完、瓶箱账对得上**

### 6.2 一天的旅程

| 时段 | 场景 | 用户动作 | 系统长什么样 | 今天 |
|---|---|---|---|---|
| 7:30 | 拣货 | 按路线拿拣货单 | 移动端拣货单：**批次先进先出**排序，啤酒/白酒分区，逐项勾选复核 | 手写单，靠老师傅记 |
| 8:30 | 装车出发 | 按排线跑 | 今日路线（周一东片…），每站明细+应回收包装 | 靠记忆 |
| 9:30 | 到店交付 | 卸货→客户点数→签收 | 电子签收/拍照；非网签留客户联；**回包装回填**（空瓶/纸箱/周转箱数） | 纸单签字 |
| 10:00 | 现结 | 当场收款 | 收款登记 | 现金口袋/转账 |
| 11:00 | 异常 | 店关门/拒收/破损 | 异常登记：拒收→订单回滚、货回仓；破损→换/补/记账 | 打电话问怎么办 |
| 15:00 | 供应商到货 | 清点卸货→入库 | 入库：**手动/拍照/语音**三种录法+批次效期+赠品破损登记 | 手录 Excel |
| 16:00 | 退货收货 | 按退货单收退货 | 数量**只能改多不能少**，一键确认入库 | 口头对数 |
| 17:00 | 无单回包装 | 客户单独要退周转箱 | 回包装单确认回库 | 本子记 |
| 月末 | 盘点 | 抽盘/大盘 | 盘点单，差异→报损审批 | 停业盘半天，扯皮 |

### 6.3 痛点 → 解法

| 痛点 | 解法 |
|---|---|
| 错发漏发（客诉大头） | 拣货单逐项复核+装车核对 |
| 手写单看不清 | 拣货/签收全数字化；入库支持拍照/语音 |
| 空瓶周转箱对不上 | 签收回填+无单回包装+押金台账 |
| 临期啤酒砸手里 | 临期预警+折价甩卖规则提醒 |

## 7. 企业主

### 7.1 画像
- 碎片时间用手机，不想学系统；可能同时是大客户经理
- 四问：**今天卖多少收多少？谁欠我钱？什么货快没了？哪个业务员强？**

### 7.2 旅程

| 时段 | 场景 | 用户动作 | 系统长什么样 | 今天 |
|---|---|---|---|---|
| 7:30 | 日报 | 躺着瞄一眼 | 推送日报：销量/回款/毛利/Top 客户/临期/异常 | 打电话问，得到模糊答案 |
| 9:00 | 审批 | 处理积压：新客户价格 2 条、特单 1 条 | 审批待办：一屏看要点，**三击完成**（通过/驳回+语音备注） | 微信翻记录，忘了就漏 |
| 12:00 | 随手查 | 看实时销售额、库存 | 看板 | 心里没数 |
| 15:00 | 大客户来电 | "老李欠多少来着" | 客户详情：应收+账龄+最近订单 | 问出纳，等半天 |
| 18:00 | 采购拍板 | 确认仓管的采购单（先付流程） | 采购审批：金额+上周动销对比 | 凭感觉 |
| 随时 | 信用特批 | 大客户超额订单 | 拦截通知→一键特批（留痕） | 电话放行，出事没证据 |
| 随时 | 摄像头 | 看办公室/库房 | 入口聚合 | 单独开 App |
| 每月 | 定绩效 | 调三指标权重 | 绩效设置向导 | 拍脑袋 |
| 每月 | 看人 | 谁开发的新客户多、谁回款强 | 员工进度排行 | 凭印象 |

### 7.3 痛点 → 解法

| 痛点 | 解法 |
|---|---|
| 账在脑子里/Excel，出门心里没底 | 四问看板+日报推送 |
| 审批靠微信吼，漏批误事 | 审批中心+超时提醒 |
| 资金去向不透明 | 采购/运营费两条审批线+费用台账 |
| 业务员在干嘛不知道 | 拜访打卡+工作进度查询 |

## 9. 从用户视角倒出的设计原则

1. **客户端：极简到"三个大按钮"**——语音/拍照/文字，专属价直显，人工兜底入口常驻。
2. **业务员：单手+语音优先**——所有录入先给语音入口；客户信息（价格/欠款/历史）一屏可见。
3. **内勤：键盘流+池子思维**——一切工作进"池"（订单池/待回录/待审批），不丢单比快更重要。
4. **仓配：大按钮、抗环境**——户外可读、拍照/语音代替打字； destructive 操作（确认收货）要防误触。
5. **老板：推送>查找，三击闭环**——日报推到眼前；任何审批不超过三次点击。
6. **双轨期人性兜底**——非网签客户的纸质流程不歧视、不阻断，用"待回录区"平滑过渡。
